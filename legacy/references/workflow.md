## 1. 输入与内容单元

先按 SKILL.md 的简短内容策略判断受众与价值，并按[知识查询](knowledge-query.md)复用现有 SW MCP 连接。问题和规划需求也可作为入口：先明确暂定选题及素材需求，再搜索、读取原文、提取归入该题素材并判断是否足够；够用即停，不足补查，最多三轮后转其他路径。策划素材先保存到 `planning/<选题标识>/materials.md` 或已有等价位置，只有进入生产才建立内容单元。纯制作修改复用已核对依据。采用的线上原文引用留在 `00-source/knowledge-evidence.md`，不把检索命中直接视为专业确认或公开授权。


支持会议纪要、访谈/咨询记录、培训与课程材料、客户拜访文稿、学员反馈、视频或录音转写、员工背景补充。

每份材料至少登记：来源、日期、提交人、涉及人物/企业、公开范围、授权、敏感点、希望表达和明确禁用内容。公开范围使用 `public`、`internal`、`restricted`；没有人工判断时默认为 `internal`。

内容单元：

```text
output/NN-选题名称/
├── 小红书/
├── 公众号/
├── 短视频/
└── AIworkspace/
    ├── 00-source/
    ├── 10-shared-assets/
    ├── 20-xhs/
    ├── 30-wechat/
    ├── 40-video/
    ├── 50-final-review/
    ├── 90-archive/
    ├── content-plan.md
    ├── manifest.json
    └── state.json
```

第一层目录不可增加 README、草稿、清单或散落素材。`.DS_Store` 可忽略。

## 2. 自动生产主线

```text
材料 / 问题 / 规划需求
  -> 明确选题与素材需求
  -> 按缺口搜索、读取原文、提取归入选题素材
  -> 判断是否足够：够用停止，不足补查，三轮后转其他路径
  -> 选题进入生产后登记与保留来源
  -> 提炼来源事实/AI 推导/机构观点/风险
  -> 选择一个可成立的选题
  -> 共享视觉资产
  -> 小红书候选 + 公众号正文/内容图/双封面候选
  -> 同页验收
  -> 人工确认
  -> 提升为当前平台成品
  -> 人工发布
```

视频并行分支：

```text
统一编辑判断
  -> voiceover-draft.md：直接写候选，内容检查后交用户
  -> 员工确认内容
  -> tts-input.txt
  -> voiceover-report.json 通过
  -> 员工在海外 MiniMax 手动生成、试听、下载
  -> 音频回传
  -> 保留原音频并质检
  -> 可选保调变速生成新工作音频
  -> 稿音匹配 + 当前工作音频词级对齐
  -> alignment-report.json 通过
  -> visual-treatment.md：全片视觉命题、母题、主体接力、相机与 按内容划分的若干幕节奏
  -> visual-explanation-map.md：全部动态知识拍的认知变化与主要视觉任务
  -> shotbook.json schema v3：逐镜画面叙事、三平面运动、主体生命周期、相机句、双向交接与语义锚点
  -> storyboard-report.json 通过
  -> 内容驱动的视觉设计 + 专业解释动画 + 字幕
  -> Remotion 画面
  -> 人声+固定 SW 原创品牌 BGM+音效
  -> mix-report.json 与品牌 BGM 指纹通过
  -> 人工确认
  -> 当前视频成品
```

小红书和公众号完成即交付，不等待口播审阅或视频音频。

## 3. 文件状态

`state.json` 使用以下阶段：

- `initialized`
- `source-reviewed`
- `xhs-candidate-ready`
- `wechat-candidate-ready`
- `review-ready`
- `video-voiceover-review`
- `video-waiting-audio`
- `video-audio-received`
- `video-candidate-ready`
- `human-confirmed`
- `manual-publish-ready`
- `published`
- `blocked`

只在真实达到时更新。`published` 必须有实际平台链接或内容 ID，不从目录位置推断。

## 4. 修改与归档

候选与已确认成品使用不同的版本依据：候选报告绑定当前源文、场景、音频及审阅输入，任一变化都必须重新验收；提升时将通过的报告快照保存在 AIworkspace 并记录稳定指针。已确认成品读取自己的快照及成品文件指纹，不跟随下一轮 current/output 报告变化。不得为了通过新验收而给缺证据的旧版本补写通过状态。

- 工作候选直接在对应 `current/` 内迭代；重要决策记录在 `review.md`。
- 平台目录已有当前成品时，提升新成品前先归档完整旧成品。
- 归档目录只读保留，不删除；新审核结论不追溯覆盖旧版本。
- 内容、图片或 HTML 改变后重跑平台检查和最终验收页。
- 公众号标题、封面主视觉、裁切焦点或样式 token 任一改变后，900×383 与 500×500 两张封面都必须重新生成；旧封面检查报告立即过期。
- 口播正文变化使原确认失效；机器稿变化重跑 voiceover-qc，音频变化重跑对齐和视频检查。
- 最终验收页按平台原子状态构建：画面、正文和复制载荷必须同时就绪；任一缺失时显示原因、禁用对应按钮并停止提升。
- 音频经过变速、剪切、降噪或转码后，派生文件成为新的唯一时间轴；从稿音匹配、词级对齐、字幕和镜头起全部重建。旧时间码整体乘除倍速只能用于诊断，不能作为最终字幕证据。
- 片级导演方案、视觉解释地图、SHOTBOOK、场景或最终口播任一改变后，`storyboard-report.json` 立即过期；专业机制不能做成术语大字，案例必须有对象/动作/结果，边界必须可见。
- 视频画面只在镜头边界切换；字幕边界不得触发整帧淡入淡出或动画重置，成片须通过黑闪和三帧内往返强切检查。
- 短视频不使用纸纹、卷边、胶带或纸片拼贴；按内容设计人物互动、关系变化、对照和证据画面。旧纸片分镜必须重新设计。
- 视频第一镜从 0 秒开始即为 1080×1920 正式封面；独立封面从同一首帧导出。复用小红书的主题与主视觉时重新编排 9:16，并在发布页人工复核裁切。

## 5. 跨平台共享

- AI 封面、获授权原始图、专业解释图和素材清单放在 `10-shared-assets/`。
- 小红书与短视频可共用同一张无文字主视觉；两平台的文字排版分别按 3:4 与 9:16 生成，不直接拉伸整张成图。
- 小红书封面图可复用到公众号，但公众号至少一张图片必须直接服务于论点；Logo 或纯装饰不算。
- 公众号双封面可复用共享无文字主视觉，但必须按 900×383 与 500×500 分别裁切，保持同一标题、同一选题和工作坊教案·红；不能把 3:4 小红书整图直接缩贴或拉伸。
- 公众号的实质技术解释图可复用到小红书内页，或作为短视频 `evidence-focus` 的技术依据；保持来源、授权和版本一致。
- 公众号文章长截图、双封面、小红书轮播整页、联系表和其他平台排版成品不得进入视频时间轴。短视频从知识逻辑重新构造 Remotion 关系、因果、流程、对比和边界场景；无文字共享主视觉、原始证据或实质技术解释图可选用并记录原路径、用途与 SHA256，但不设“至少复用 1 张平台图”的指标。
- 不直接覆盖共享资产；使用稳定文件名加版本或更新资产清单后再替换引用。
