# 短视频生产规范

> v1.13 新候选优先采用 [全片导演执行契约](director-contract.md)。旧版逐镜字段清单仅用于历史 schema；新候选以精简 direction、编译结果和实际审片为准。

## 1. 口播内容稿

默认 45–90 秒。先解决内容，再处理机器标记。创作与交稿见 [口播创作与检查](science-script.md)；本文件不能代替该流程。

可参考的结构（按材料选择，不强制每题有冲突或行动建议）：

```text
具体冲突/错误动作
  -> 为什么常见答案无效
  -> 一个更深的专业判断
  -> 生活化例子或对比
  -> 边界
  -> 下一步行动/官方 CTA
```

要求：

- 前 3–5 秒呈现具体观察、场景、问题或有依据的冲突，让观众知道为何值得听；
- 句子短、能说出口，允许少量“你想一下”“其实”“那问题来了”等自然连接词；
- 口癖有节制，同一词不要机械重复；
- 术语先用人话铺垫，再给专业名称；
- 不用材料不能支撑的 `90%`、`一半`、`所有人` 等绝对数字；
- SW 官方机构叙述贯穿口播、字幕和 CTA。

口播写好并检查后先交用户；不要求先填 Brief、钩子、知识链或独立审稿表。机器稿以用户确认的自然口播为准。

### 口语表达检查

`voiceover-draft.md` 不是把公众号正文缩短，而是能直接讲出口的内容稿。按内容判断以下表达是否有效，不按口语关键词计数验收：

- 开头尽快呈现本题价值，可以平实观察或场景进入；
- 对话、反问、定义或背景说明按理解需要使用，不为了达标添加；
- 转折来自前后逻辑，不要求出现固定口语词；
- 长短句交替，单句一般不超过 65 个非空白字符；
- 结尾明显减速，落到一个问题、一个动作或 SW 官方 CTA。

口语连接词用于模拟真实讲话，不得机械填充，也不得为通过检查重复同一个口癖。

## 2. MiniMax 唯一机器稿

`voiceover-draft.md` 经员工确认后，必须做一次“机器口播化”，生成唯一 `tts-input.txt`。不要再创建内容相同的“标注稿”“完整口播稿”或“干净版”。机器口播化只调整发音、标点、分段和稀疏停顿，不得悄悄改变已经确认的观点或事实。

- 先写清四段语气曲线：开头直接、冲突加强、专业解释放稳、结尾减速落地；该逻辑记录在 `tts-settings.md`，不另建第二份标注稿。
- 用标点、短句和段落形成主要节奏；不能只把 `MBTI` 换成 `M B T I` 就视为机器稿完成。
- 对 45～90 秒、约 250～650 字的常规稿，使用 3～6 个显式停顿，通常为 `<#0.3#>`、`<#0.4#>`、`<#0.5#>` 或 `<#0.6#>`；停顿只放在钩子完成、观点反转、例子结束、结论落地等语义边界。
- 禁止连续停顿、每句都标停顿、单句内部无意义切断或使用未经当前海外 MiniMax 页面验证的情绪代码。自然标点仍承担大部分节奏。
- 英文字母需拆读时在机器稿中加空格：`MBTI` 写成 `M B T I`，`Fi` 写成 `F I`，`Fe` 写成 `F E`。公开字幕和文稿仍使用标准写法。
- 先用 1–2 句短样测试新模型或新声线，再生成全稿。
- 员工在网页端选择有授权的声音、试听并下载；Skill 不保存账号、Cookie 或密钥。

生成后必须运行：

```bash
node <SKILL_DIR>/scripts/voiceover-qc.mjs \
  --draft <内容单元>/AIworkspace/40-video/current/voiceover-draft.md \
  --tts <内容单元>/AIworkspace/40-video/current/tts-input.txt --confirm YES \
  --report <内容单元>/AIworkspace/40-video/current/voiceover-report.json
```

检查失败时不得把机器稿交给员工生成音频。机器检查只验证结构与标记，员工仍要试听自然度、重音和老板声线的实际表现。

## 3. 音频回传与质检

把原始音频放到 `AIworkspace/40-video/current/audio-inbox/`。保留原文件，不覆盖、不先转码替代。

检查：

- `ffprobe` 可解码、时长、采样率、声道和编码；
- 首尾是否截断；
- 是否有重复句、长静音、爆音、异常女声/男声或背景人物；
- 内容是否与确认稿一致；
- 语速、重音、自然度和专业词读音是否可接受。

不通过时只返回准确时间点和修改建议，等待员工重新生成音频。

### 音频派生与唯一时间轴

原始音频始终只读保留。需要变速时使用保调处理，不通过修改采样率制造升调或降调：

```bash
node <SKILL_DIR>/scripts/prepare-audio.mjs \
  --input <视频工作区>/audio-inbox/returned-voice.wav \
  --output <视频工作区>/audio-work/voiceover-working.wav \
  --speed 1.2 \
  --report <视频工作区>/audio-transform-report.json
```

脚本会记录原始/派生音频 SHA256、时长、实际 `atempo` 链和完整解码结果。任何变速、剪切、降噪或转码都会创建新的工作音频；后续字幕、镜头、BGM 入点和成片时长只认该文件。禁止直接覆盖 `audio-inbox/`，也禁止把旧 SRT 整体除以或乘以倍速后作为最终字幕。

### 稿音匹配与词级对齐

1. 使用本地 Faster-Whisper、WhisperX 或等价的词级时间对齐器处理当前工作音频，保存原始证据 JSON。模型输出只用于时间锚点和稿音比较，不直接作为公开字幕正字。
2. 将拟采用的确认稿与 ASR 规范化比较。明显不匹配时必须停止：要么请员工重新生成匹配音频，要么经员工确认后改用与实际音频一致的口播稿。不得把计划稿强塞进字幕。
3. 在 `final-voiceover.md` 中只保留与实际音频一致的完整公开正文，不写标题、说明或审核记录。对 `外向/外相`、`判型/判刑` 等 ASR 同音错误，使用确认稿的专业正字。
4. 字幕按语义分组，通常每条 8～18 个汉字、至少 1.2 秒；静音处允许字幕留白。人工至少抽查开头、中段、结尾三个词级锚点。
5. 生成并锁定当前报告：

```bash
node <SKILL_DIR>/scripts/alignment-qc.mjs \
  --audio <视频工作区>/audio-work/voiceover-working.wav \
  --source-audio <视频工作区>/audio-inbox/returned-voice.wav \
  --transform-report <视频工作区>/audio-transform-report.json \
  --script <视频工作区>/final-voiceover.md \
  --scenes <视频工作区>/scenes.json \
  --evidence <视频工作区>/alignment-evidence.json \
  --report <视频工作区>/alignment-report.json
```

`alignment-report.json` 必须证明：当前工作音频哈希一致、稿音相似度达标、词级时间戳存在、人工锚点不少于 3 个、字幕文本与 `final-voiceover.md` 规范化后完全相等、无重叠、无越界且最短时长合格。任一输入改变后必须重跑；旧报告不能复用。

## 4. 视听脚本与画面

通过稿音匹配的当前工作音频是唯一时间轴。先转写/对齐，再生成：

- `audio-report.json`
- `audio-transform-report.json`（发生派生处理时）
- `alignment-evidence.json`
- `alignment-report.json`
- `final-voiceover.md`
- `visual-treatment.md`
- `visual-explanation-map.md`
- `shotbook.json`
- `storyboard-report.json`
- `scenes.json`
- `subtitles.srt`
- `animation-notes.md`
- Remotion 工程

第一阶段视觉基线：

- 1080×1920、30 fps；
- 上方 SW 品牌/栏目区，中间为主要解释动画和场景区，下方为字幕、页码或品牌收束区；
- 使用完整官方 Logo；暖白/浅灰画布、炭黑正文、SW 深红强调，可用少量冷色辅助区分概念；
- 短视频不使用纸纹、卷边、胶带或纸片拼贴；按内容设计人物互动、关系变化、对照和证据画面。旧纸片分镜必须重新设计。
- 公众号文章长截图、双封面、小红书轮播整页、联系表和其他平台排版成品一律不得进入视频。可选用无文字共享主视觉、原始证据或实质技术解释图，但图片复用不是完成指标；
- 字幕按语义短句分组，不遮挡主体，不把整段文字一次铺满。

先按 [视觉解释导演](visual-direction.md) 完成片级导演方案，再证明每个知识点的认知变化和画面解释价值，最后才进入 [Remotion 逐帧视频实现规范](remotion.md)。动画组件是实现结果，不是创意起点；专业机制、案例与边界不能只换成大字或抽象装饰图。


### 首帧封面硬规则

封面同时承担“视频第一帧”和“平台独立上传封面”两个角色。二者必须来自同一张 1080×1920 首帧，不允许各做一版后产生点击前后跳变。

- `scenes.json` 第一镜必须 `start=0`、`visual=cover`，并使用 `assets/cover.png` 的 AI 无文字位图或获授权真实素材。首帧不得先出现黑帧、Logo 动画、空白页或普通正文页。
- 优先沿用同内容单元小红书封面的核心钩子、主视觉和「工作坊教案·红」语言，但必须重新编排为 9:16；禁止把 1080×1440 小红书成图直接拉伸、上下补边或整体缩小贴入视频。
- 视觉结构固定为“轻量官方品牌区 + 相关位图主视觉 + 一句核心标题 + 可选一句补充”。主视觉约占中部有效区 45%–60%；不放正文段落、页码、目录、多个并列卖点或内部流程标签。
- 标题总长 4–28 字，按语义拆成 1–3 行，每行不超过 14 字；标题参考 64–84px，补充句参考 26–34px。只强调一个关键词，不用多色描边、发光字或促销贴纸。
- 画布为 1080×1920。把标题和关键人物/物体放在中央 3:4 安全核心区内（基线 `x=60–940`、`y=240–1680`），并为右侧互动按钮和底部字幕/账号信息保留空间。由于平台展示入口和裁切可能调整，发布前仍须在视频号发布页预览实际裁切。
- 封面镜头至少持续 1.8 秒，通常随第一句钩子保持 1.8–3.5 秒；不额外插入与口播无关的静默片头。第一镜持续更长时，应通过主体局部动作或信息递进保持观看感，而不是 8 秒静态海报。
- `scripts/build-video.mjs` 必须输出 `output/video-cover.png`，并验证它是 1080×1920、素材没有低分辨率放大、标题处于安全区、和视频解码后的第一帧 SSIM ≥0.98。

推荐字段见 `assets/templates/video/director-contract.example.json`，每次先填写 `cover-brief.md` 再生成第一镜。

### 时间稳定硬规则

- `scenes.json` 的镜头边界决定画面切换；字幕边界只更新字幕层，不得被当作新镜头。
- 常规镜头不得短于 1.8 秒，优先保持 2.5–8 秒；字幕不得短于 1.2 秒。需要更短的强调镜头时必须在分镜中明确标注并人工复核。
- 音频中的无字幕空隙沿用前一镜头，不能因为没有命中镜头区间而跳到最后一镜或其他默认画面。
- 默认稳定直切。需要转场时，只在镜头边界使用一次 6–12 帧过渡；禁止给每条字幕首尾加整帧淡入淡出。
- 缩放、位移等连续动画以整镜头为周期，字幕变化不得让动画从初始值重新开始。
- 主画面动作必须服务理解，必要时允许静止；不把字幕的变化算作主画面动画，超过 2.6 秒的静止作为审片线索，允许有目的的阅读停顿。
- 禁止非脚本化的整帧黑闪、白闪、透明帧，以及三帧内“切出去又切回来”的往返强切。

生成后运行：

```bash
node <SKILL_DIR>/scripts/video-qc.mjs \
  --input <内容单元>/AIworkspace/40-video/current/output/video-candidate.mp4
```

报告要求 `blackEvents=[]`、`rapidFlashPairs=[]`、`passed=true`；`freezeEvents` 中的静止段交导演解释。同时 `video-report.json` 必须记录 `render.engine=remotion`、`frameDriven=true`、`staticLoopClips=false`、`knowledgeLogicRenderer=native-remotion`，并证明 `platformLayoutScreenshots=[]`。允许的原始证据、技术解释图或共享主视觉另列资产清单；图片复用不是完成条件。机器检查通过后仍须以正常速度完整观看一次，并在镜头切换点前后逐帧抽查。

## 5. BGM 与音效

- 所有 SW 短视频固定使用 `assets/bgm/sw-brand-bgm.mp3`。这是用户确认的 SW 原创品牌音乐，资产 ID `sw-brand-bgm-v1`，SHA256 `0be398827ba3f1b4a297748b9b49f6b104d0db5549f08471daf7cc98892b9c7c`；权属凭据线下保管，Skill 内声明不替代法律文件。
- 不得自行换歌、下载库存音乐、加入第二首 BGM、把音效当 BGM，或在文件缺失时输出无音乐候选。允许按成片长度调整同一母带的截取起点、淡入淡出和侧链参数。
- 默认尽量从母带第 60 秒开始；若片长超过剩余时长，自动前移起点以避免不必要的循环。可在 `scenes.json` 用 `brandBgmStartSeconds` 指定同一母带的其他起点，但不能更改 `brandBgm` 路径。
- 旁白清晰度优先；当前基线沿用已试听样片的 `-2 dB` 预增益与轻侧链（threshold 0.03、ratio 2.2、attack 18 ms、release 320 ms）。这些参数是可复现起点，不替代完整人工试听。
- `build-video.mjs` 必须生成 `output/mix-report.json`，记录母带 ID、SHA256、实际起点、淡入淡出、侧链、工作人声及最终混音指纹；`video-report.json.assets.brandBgm` 与 `audio.mix` 必须一致。
- BGM 必须在手机外放中可感知，不能小到形同不存在，也不能遮盖口播。机器通过后仍要用手机外放和耳机各完整试听一次。
- 开头、观点反转、章节切换和结尾可用少量音效；不要每句话加提示音。
- 音效仍须明确来源和授权；固定 BGM 规则不自动授权其他声音素材。

## 6. 交付

人工确认后，`短视频/` 只保留当前成片、`video-cover.png`、字幕和最终口播稿。原始音频、分镜、工程、分轨、`video-report.json`、`video-temporal-report.json` 和旧版本留在 AIworkspace。首帧封面或闪烁检查未通过时不得把视频称为候选成片。
