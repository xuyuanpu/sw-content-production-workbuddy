# 公众号制作规格

首次进入制作阶段运行 `node <SKILL_DIR>/scripts/prepare-platform.mjs --unit <内容单元> --platform wechat` 补齐所需模板和品牌素材；已有文件不覆盖。

写作已完成并需要制作时才读本文件。

## 制作输入

正文 1000～1500 个 Unicode 字符；含副标题、导语、章节、引语、图注和文内 CTA，排除主标题与固定品牌壳。不以图片藏字规避范围。至少一张直接解释论点的内容图，装饰和 Logo 不计。材料不足时先交候选并指出扩展所需素材，不填空话。

## 版式

- 使用工作坊教案·红：暖白底、炭黑正文、深红章节和批注线。
- 390px 移动端单栏，正文 17px 左右，行高约 1.9；保持短段落。
- 主标题使用深红左边线或短批注标记；章节之间有明确但克制的层级。
- HTML 使用内联样式、相对本地图片或数据 URL，不依赖远程字体、CSS、脚本或图片。
- 图片清晰、不放大；实际粘贴到公众号后台后仍需检查样式清洗、图片重托管、手机和深色模式。

## 标准化双封面

- 每篇文章必须生成两张同源封面：`cover-wide.png` 为 900×383，用于公众号头条封面；`cover-square.png` 为 500×500，用于分享卡片、次条或方形入口。
- 两张封面必须来自同一张无文字、高分辨率主题主视觉；主视觉只能是 AI 生成位图、品牌自有图或已获授权素材，且至少提供 1000×1000 的可裁切像素。不得低分辨率放大。
- 封面使用工作坊教案·红、SW 官方 Logo 和“SW 官方 / 专业解读”机构口径。主标题必须与 `article.json.title` 完全一致，按语义拆成 1～3 行；允许一句不超过 24 字的副标题，但不得新增文章没有承担的承诺。
- 封面必须服务本篇选题，不能用正文专业解释图、固定品牌头尾图、二维码、Logo 单图或通用库存图冒充。
- 双封面属于公众号发布载荷，不计作正文的“实质内容图”。后台上传前仍需人工检查头条、分享卡片和次条裁切预览。

## 固定品牌壳

每篇公众号在正文计数区之外固定保留以下顺序：

1. `brand-header.gif` 原始头图；
2. 1000～1500 字正文与实质内容图；
3. 下列两段品牌介绍原文；
4. `brand-footer-group.png` 与 `brand-footer-channels.webp` 两张原始尾图；
5. 下列三行商标说明原文。

## 自动生产步骤

1. 将 `AIworkspace/30-wechat/current/article.example.json` 复制为 `article.json`。
2. 写入标题、摘要、导语、通常 3–5 个章节、段落、实质内容图、图注、边界和结尾动作；同时填写 `cover.src`、有意义的 `cover.alt`、与文章标题完全一致的 `cover.titleLines`、可选副标题和裁切焦点。章节数量服从论证，不为凑数机械拆分。
3. 将共享专业图复制为 `assets/content-image.png`，将无文字主题主视觉复制为 `assets/cover-image.png`；两者可以来源相同，但必须分别满足“正文解释价值”和“封面裁切”要求。保持 `assets/logo.png` 和三张固定公众号品牌图与 Skill 原件一致。
4. 运行 `node <SKILL_DIR>/scripts/build-wechat.mjs --unit <内容单元路径>`，一次生成 `output/article.md`、`article.html`、`share-copy.md`、移动端长图、`cover-wide.png`、`cover-square.png` 和检查报告。缺封面、尺寸错误、标题不一致、主视觉不足 1000×1000 或浏览器检查失败时命令必须非零退出。
5. 少于 1000 字时优先补足由材料支持的论证链、例子、专业边界或行动建议；超过 1500 字时压缩重复表达和旁枝，不删边界、不藏字，然后重新运行同一命令。

## 候选交付

- 1000～1500 字 `article.md`；
- 单文件/自包含 `article.html`；
- 由最终 HTML 直接渲染的 780px 宽移动端长图；
- 至少 1 张实质内容图；
- 900×383 `cover-wide.png` 与 500×500 `cover-square.png`；
- `share-copy.md`；
- 检查报告留在 AIworkspace。
