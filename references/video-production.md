# SW 全片导演与统一执行链

首次进入制作阶段运行 `node <SKILL_DIR>/scripts/prepare-platform.mjs --unit <内容单元> --platform video` 补齐所需模板和品牌素材；已有文件不覆盖。

本文件是短视频方向、视觉选择与执行入口的唯一规则源。SKILL 入口及小黑技能引用这里；不再按每轮返工追加一套并行规则。

## 先设计真实画面，再编排执行

把口播当作连续的理解过程：先判断观众此刻不知道什么，再设计谁在做什么、哪个对象发生什么变化、下一句如何接续。不要先挑模板，再把句子填进格子；一句话不必换一页，同一个情境可以承接多句话。动作应兑现内容，例如提问后出现更具体的经历、倾听者的回应改变、双方共同核对一个答案，而非仅给“认真倾听”配两个不动的人。

先用现有 direction.visualStory、openingFrame/closingFrame 和 handoff 写清可见事件，再制作素材和组件。无需新增平行策划表。允许自由选择生成配图、对象动画、文字、图形或其组合；不用词义分类代替导演判断。

造型参考见 [已认可的编辑插画](../assets/art-direction/editorial-characters-reference.png)，这是风格参考，不是每条视频的通用素材或构图模板。

人物不再默认调用小黑 IP 技能；仅当用户明确选择小黑时才使用对应技能，当前编辑插画方向不受其黑色豆形人物规则约束。生图使用宿主可用的图像工具，传入认可的参考图及当前情境；不能把“写了提示词”记录为“素材已生成”。

本项目已经认可的参考方向是自然成人比例、简洁平涂、有表情的编辑插画。复用已认可的造型语言，不把特定人物、姿势或构图固定为所有主题的默认答案。需要人物情境时，优先准备真正适合动作的配图或姿态组，保持脸、衣服与身份标识一致；不能因素材缺失便用粗糙几何小人冒充同等质量。新造型先看真实出图，已有认可方向可由模型自行推进，不反复要求用户批准。

图片是白底局部插入素材，画幅仍由品牌背景、标题、字幕与独立对象构成。身份影响理解时，标签直接画入人物衣服或图内对应位置。姿态组之间的切换或溶解只能称为姿态切换；需要连续肢体动作时必须提供可分层素材或实际关节动画，不能把整图推拉称为人物表演。

实际画面是决策依据：配图生成后先检查，接入镜头后运行视觉试稿，发现情境没有表达内容就回改素材或动作。不能仅因字段齐全、技术 QC 通过就进入交付。

## 一份全片方案

只手写 scenes.json：film、逐镜 direction、explanations、真实音频锚点。knowledge-chain.md、visual-treatment.md、shotbook.json、visual-explanation-map.md 均由编译器派生，不手写或来回同步。explanations 按这篇实际内容列出需要解释的点，不要求每条视频必有机制、案例和边界三类镜头。


沿用 content-plan 和用户确认稿的判断，不重新策划主题；配音后以 `scenes.json` 为唯一画面计划：

- `film.audience / viewerChange / throughline`：观众处境、理解变化与贯穿对象。
- `film.cover.subject / action / topicLink`：首页画什么、发生什么、为什么直接关联主题。生图前写清。若只能靠事后讲寓意才关联主题，重做选图方向。
- `film.visualDivision / sound`：全片图像、人物、对象动画与声音的分工。
- 每镜 `direction`：knowledgeBeats、viewerBefore/After、visualStory、openingFrame/closingFrame、primaryVisualJob、handoff.fromPrevious/toNext。选择由本句认知任务决定，不为凑模板或比例补镜头。
- `explanations`：知识点对应的来源、画面依据和镜头；before/after 由对应镜头 direction 自动带入，不另写一遍。
- `captions`：当前确认口播的短字幕，使用真实语音 from/to 锚点。

编译器从同一计划派生 `knowledge-chain.md`、`visual-treatment.md`、`shotbook.json`、`visual-explanation-map.md` 与秒数。它们是阅读视图，不另行创作或手改。内容稿件的来源与人工确认记录仍保留，不能由分镜反向伪造。

## 组件选择由导演决定

先说明这一句要让观众理解什么、画面开始和结束分别是什么状态，再选组件及动作。`primaryVisualJob` 和 `explanations.operation` 用自然语言说明意图；没有“解释→因果图”“差异→双栏”“边界→红绿卡”等语义映射或镜头配额。

新画面可用 `visual: "composition"` 和 [组件库接口](component-library.md)：文字、图片、矩形、椭圆、路径、连接线、分组可自由组合；按真实语音锚点编排位置、尺寸、显隐、缩放、旋转与路径显现。可重复调整同一对象，不限制为一次入场、一次移动。不限制为五个对象或四字标签；内容密度和手机可读性由实际画面判断。

先考虑哪种可见变化能帮助理解，不为展示组件而装饰。允许同样含义使用不同组合，也允许同一组合用于不同含义。几何形状不自带语义；连接线只表示导演明确说明的关系，箭头必须显式选择并有内容依据。聚合、拆分、对照可以用空间变化、遮罩、图像或文字实现，不强制连线。

旧 `cover`、`comparison`、`object-motion`、`boundary-split` 等保留为可选预制组合及旧片兼容。它们自身有固定布局和动作限制；看过实现、确认适合当前内容后才采用。预制组合的限制不适用于 composition。不得通过更换文字冒充新的解释设计，也不为避免重复强行换一个不合语义的组件。

首页仍使用与主题直接相关的生成主视觉，并保留品牌识别；正文人物插图作为白底局部配图，身份影响理解时将短标签直接画入人物，跨镜一致。模型决定大小、位置及与其他组件的配合；不用整张图缩放冒充情境内部的过程变化。不同偏好只在脚本有依据时标记，不从行为判型。

保留原主题色、字体、Logo、独立字幕层和固定 BGM。任何场景均不使用纸纹、卷边、胶带或纸片拼贴；不得把图文平台整页截图作为视频素材。图片资产仍走统一路径、来源和指纹检查。

## 时间与校验

`video.directorVersion=1`；音频与词级证据绑定 SHA256。第一镜从 0 开始，其余镜头由 startAnchor 派生；最后一镜覆盖实际音频。composition 的关键帧由 anchor、edge 和 offset 编译，不手填 at。

程序检查组件及状态是否支持、引用是否存在、时间是否合法、当前资产是否可用；字体过小、内容超出容器和重复文字镜头作为审阅线索。机器不凭组件名判定语义正确，也不替导演断言画面没有误导。结合实际帧检查可读性、遮挡及关系含义，再完整观看试听；静止时长只是线索，不为消除报警添加无意义运动。

旧镜头沿用 `beats` 接口。相机与整体主体交接缺省静止；需要时明确给路径。不存在的动作或词锚点报错，不静默回退。

## 一个构建入口

```sh
node scripts/produce-video.mjs --unit <内容单元> --workspace <视频工作区> --check
node scripts/produce-video.mjs --unit <内容单元> --workspace <视频工作区> --proof --at 0,8.5,16
node scripts/produce-video.mjs --unit <内容单元> --workspace <视频工作区> --preview
```

同一入口依次执行编译、当前稿确认检查、稿音对齐、分镜校验和 build-video。`--check` 仅检查输入，不渲染。`--proof` 使用同一 Remotion 实现只渲染选定帧，输出 `visual-proof/index.html` 与绑定输入和时间轴的 `review.json`，不生成或覆盖候选视频、不混音；省略 `--at` 时取每镜开始、中间、结束附近。它需要已确认口播及真实音频以确定时间轴，配图本身可更早试稿。静帧只能检查构图与状态，运动和声音仍要看片。`--preview` 从正式候选复制全片；可用 `--from / --to` 从候选截取代表片段。全片预览与候选文件字节相同，片段沿用其画面与混音。为避免两套实现，当前片段预览也先构建完整候选，因此不是低成本试片；正式候选未变时可复用已生成候选来截取，不另起渲染实现。

旧 `render-director-preview.mjs` 只转到此入口，不再自建渲染或只混人声。禁止为“快速测试”另写 render.mjs 或复制整套组件到内容目录。低层 compile/qc/build 命令保留供诊断；不构成另一条默认生产路。

正式混音使用固定品牌 BGM：先按原规则 ducking，再固定乘一次 `postDuckGain=0.6`，人声增益不变。从母带及原始工作人声重新计算，不对上次成片反复乘0.6。参数以 bgm-policy-lib.mjs 为准；预览与候选不得各调一套。

## 检查结果与回改

构建候选后自动从实际编码视频提取每两秒及镜头边界附近的画面，生成 `output/visual-review/index.html`。页面并列显示当时字幕、画面意图和真实截图，并能定位视频播放；其报告绑定视频 SHA256。检查整段时间轴，不能只挑好看的开头和结尾。抽帧是发现空洞、遮挡、图文矛盾的线索，不能代替完整观看与试听。

导演审阅记录应写实际观察及位置，例如哪一段提问后画面出现了新的经历，或哪一段人物始终没有回应；不用“通过、流畅、美观”代替证据。不要求每两秒必须变化，也不为消除静止提示添加装饰运动。


- 音频/锚点/资产/字幕/渲染等技术错误：停止并记录失败步骤。
- 以当前稿件的人工确认与机器稿检查作为制作输入，不强制独立文字审稿；真实音频、技术验收和完整视听审片仍需通过。
- 技术渲染成功但缺少全片观看/试听：`rendered-awaiting-review`，不等于可发布。静止超过2.6秒是审阅线索，不为消除报警添加装饰运动。
- 完整审片后填写绑定当前视频和时间轴的 `output/director-review.json`；未看/未听保持 false。发布仍由人确认，promote 再检查当前输入绑定与导演审阅。

每次回改先定位层级：论点问题回脚本；主题关联问题回 film.cover；人物情境问题回配图；过程关系问题回对象/边/动作；声音问题回唯一混音配置。随后重跑同一入口。禁止仅修输出文件却沿用旧报告。

机器能证明输入一致、动作执行和文件有效；不能证明图片贴题、解释清楚或专业结论正确。导演仍需看真实画面、听声音，并记录具体观察。
